# Ma Finance — SPEC

App web 100 % locale (aucun backend utilisé, aucun compte). UI en français, devise €.
Le backend FastAPI du template reste en place mais n'est PAS utilisé par l'app (exigence utilisateur : données uniquement sur l'appareil).

## Stockage
- IndexedDB `ma-finance` / store `kv` / clé `data` → objet `AppData` complet (src/lib/store.ts), sauvegarde auto (debounce 250 ms) après chaque modification. Fallback localStorage `ma-finance-data`.
- Préférences (filtre compte, année, interrupteur virements internes) : localStorage `ma-finance-prefs`.
- Premier lancement : `src/data/releve-revolut.csv` (relevé Revolut COMPLET depuis l'ouverture, nov. 2019 → oct. 2026, SEED_VERSION=2) est parsé (src/lib/revolut.ts) puis catégorisé par les règles par défaut.

## Modèle (src/lib/types.ts)
Account, Transaction (montant signé, type income|expense|transfer_in|transfer_out, internal, source import|manual|recurring, catStatus auto|manual|to_review), Category, Rule (conditions ET, catégorie, type optionnel), Recurrence (fréquence, fin never|date|count|amount, statut), Goal (cible, alloué, historique d'allocations).

## Règles métier
- Résultat net global : virements internes exclus sauf si l'interrupteur « Inclure les virements internes » est activé (alors transfer_in → revenus, transfer_out → dépenses).
- Récurrences : au démarrage, les échéances ≤ aujourd'hui sont créées (source recurring) et la prochaine échéance avance ; prévu = échéances futures dans la période.
- Règles : première règle active correspondante ; catégories manuelles jamais écrasées ; pas de correspondance → « Non classé » / À vérifier. Correction manuelle → toast proposant de créer une règle (/regles?desc=…&cat=…).
- Objectifs : répartition virtuelle ; alerte si total alloué > solde réel épargne.

## Fonctionnalités v2
- Détecteur d'abonnements (src/lib/subscriptions.ts, page Récurrences) : dépenses non internes, même marchand (description normalisée), montant ±10 % du dernier, ≥3 mois consécutifs (trou d'1 mois toléré), dernière occurrence < 45 jours, non couvertes par une récurrence existante. « Suivre en récurrence » crée une récurrence mensuelle en 1 clic ; « Ignorer » stocke la clé dans `dismissedSubscriptions`.
- Budgets (src/lib/budgets.ts, page /budgets) : `Budget {category, amount (défaut mensuel), overrides{"YYYY-MM": montant}}`. Dépensé = dépenses réelles (hors internes) de la catégorie, tous comptes EUR. Niveaux : ok <80 %, warn ≥80 %, over >100 %. Alertes : badge sur la nav, bandeau tableau de bord, toast après ajout/modif d'une opération. Vue annuelle cliquable pour ajuster un mois.
- Comptes & Pockets (/comptes, /comptes/:id) : solde, mini-courbe, transferts entrants/sortants ; détail avec évolution du solde, barres mensuelles, origines/destinations des transferts par compte, catégories de dépenses, liste des transferts. Lien « Voir les opérations » → /operations?account=<id>.

## Fonctionnalités v3
- Report de budget : `Budget.rollover` (défaut activé ; `false` = désactivé) + `startMonth`. Plafond effectif(mois) = plafond de base (défaut ou ajustement) + report, report = max(0, plafond effectif du mois précédent − dépensé), calculé depuis `startMonth` jusqu'au mois en cours. Seul le reste positif est reporté (choix utilisateur). Puce « +X € reportés ».
- Rappels d'échéances (src/lib/insights.ts `upcomingReminders`, bandeau global `RemindersBar` en haut de chaque page + toast à l'ouverture) : récurrences de dépense actives dont l'échéance tombe aujourd'hui → J+3 (étapes J-3, J-1, J ; le jour J inclut les opérations récurrentes générées aujourd'hui). Masquage par rappel stocké dans prefs `dismissedReminders` (clé recId|date|étape → un rappel masqué à J-3 réapparaît à J-1 puis J).
- Bilan du mois (`computeRecap`, `MonthlyRecapDialog`) : s'ouvre automatiquement à la 1re ouverture d'un mois pour le mois écoulé (prefs `lastRecapSeen`), puis carte « Bilan du mois écoulé » sur le tableau de bord ; navigation mois précédent/suivant. Contenu : revenus/dépenses/net réels vs mois précédent, budgets tenus, top 3 catégories, Pockets (transferts in/out, solde fin), épargne (solde début→fin, versements/retraits, intérêts, allocations objectifs).
- Tirelire de Pocket : `Account.goal {target, targetDate?, label?}` ; panneau sur /comptes/:id (Pockets) avec jauge solde/cible, reste, à verser par mois, rythme (variation moyenne 3 mois), date d'atteinte estimée ; mini-jauge sur les cartes /comptes.

## Fonctionnalités v3
- Report de budget : `Budget.rollover` (activé par défaut, désactivable par budget) + `startMonth`. Plafond effectif = plafond du mois (défaut/ajusté) + report ; report = reste POSITIF du mois précédent (les dépassements ne sont pas reportés), chaîné depuis startMonth, jamais au-delà du mois en cours.
- Rappels d'échéances (src/lib/insights.ts, components/RemindersBar.tsx, visible en haut de toutes les pages) : récurrences de dépense dont l'échéance est aujourd'hui ou dans les 3 prochains jours (étapes J-3, J-1, J ; J inclut les opérations récurrentes générées aujourd'hui). Masquables (prefs.dismissedReminders, clé recId|date|étape). Toast à l'ouverture.
- Bilan du mois (components/MonthlyRecapDialog.tsx) : fenêtre automatique à la 1re ouverture du mois pour le mois écoulé (prefs.lastRecapSeen), carte « Bilan du mois écoulé » sur le tableau de bord ; revenus/dépenses/net vs mois précédent, budgets tenus, top dépenses, Pockets alimentées, épargne (solde, versements, intérêts, allocations). Navigation mois précédent/suivant.
- Tirelire de Pocket (components/PocketGoal.tsx) : `Account.goal {target, targetDate?, label?}` ; jauge solde réel / cible sur la page de la Pocket, à verser par mois, rythme (variation moyenne 3 mois), date estimée ; mini-jauge sur la carte Comptes & Pockets.

## Fonctionnalités v4
- Épargne (src/lib/goals.ts, pages/Savings.tsx) : `Goal.kind` target|open|monthly (défaut target pour les anciens objectifs), `monthly?` (mensuel prévu), `priority?` essential|important|bonus (défaut important), statut `archived`, `reachedAck`. Validation : cible > 0 pour un objectif cible, mensuel > 0 pour un objectif mensuel, pas de montant négatif, allocation ≤ non alloué (désallocation ≤ alloué).
  - Calculs : mensuel requis = restant / mois jusqu'à la date cible ; projeté fin d'année = alloué + mensuel prévu × mois restants (mois en cours compté s'il n'a pas reçu de versement ; plafonné à la cible et à la date de fin) ; atteinte estimée = restant / mensuel prévu (sinon rythme réel 90 j). Alerte « À ce rythme, la date cible ne sera pas atteinte » si requis > prévu.
  - KPI : solde réel, alloué, non alloué, épargne mensuelle prévue (objectifs actifs), solde projeté fin d'année (réel + versements prévus + intérêts estimés = moyenne 3 mois × mois restants), état de la répartition (Équilibré / Sur-allocation de X €, non bloquant).
  - Répartir un versement : Suggérer (essentiels → date proche → en retard → importants → ouverts/bonus, chacun au plus son besoin du mois), Selon le besoin mensuel (prorata requis ou prévu), parts égales, prorata du restant, saisie manuelle ; le reste demeure non alloué.
  - Objectif atteint : badge 🎯 Atteint + actions Conserver / Archiver (fonds restent alloués) / Libérer les fonds (alloué → 0, archivé) / Renouveler (nouvelle cible ou date) / Nouvel objectif avec ces fonds (transfert, ancien archivé). Section « Archivés » repliable. Fenêtre détail (clic sur le nom) avec toutes les valeurs + historique.
  - Minimum souhaité (`Goal.minimum?`, objectifs ouverts et mensuels uniquement) : jauge ambre → verte sur la carte et le détail (« il manque X € » / « atteint ✓ ») ; pris en compte par « Suggérer » (besoin = max(mensuel prévu, manque pour le minimum), objectif sous son minimum servi en priorité comme un objectif en retard).
  - Icônes/couleurs : préréglages + bouton « Personnaliser » (emoji libre, sélecteur de couleur).
- Bilan annuel (/bilan, src/lib/years.ts, pages/Years.tsx) : chaque année depuis la 1re opération (tous comptes EUR, hors internes) : revenus, dépenses, net, taux d'épargne, variation du compte d'épargne, tendances (évolution vs N-1 — en moyenne mensuelle si une année est incomplète —, premier poste, plus forte hausse/baisse de catégorie, meilleur/pire mois), mini-barres mensuelles. Graphique « Comparaison des années » superposant mois par mois (2024, 2025, 2026 par défaut ; années activables), métriques dépenses/revenus/net/net cumulé. Vue d'ensemble en barres.
- Rappel de solde bas (`lowBalanceAlerts` dans insights.ts, bandeau rose dans RemindersBar + toast) : Pockets non archivées dont le solde actuel ne couvre pas les dépenses récurrentes actives des 7 prochains jours ; affiche le manque et la date ; masquable (clé dans prefs.dismissedReminders).
- Budgets par compte : `Budget.accountId?` (compte/Pocket EUR) + `category` ("" = toutes catégories). Périmètres : catégorie tous comptes, compte entier, ou catégorie sur un compte ; doublon de périmètre refusé. Dépensé = dépenses réelles hors internes du périmètre (`budgetSpent`, index "compte|catégorie"). Filtre Tous / Catégories / Comptes sur /budgets, libellé `budgetLabel`. Panneau « Budget du compte » sur /comptes/:id avec lien /budgets?compte=:id (ouvre le formulaire pré-rempli). Alertes de saisie et bilan du mois tiennent compte des budgets de compte.
- Préparer le mois suivant (/budgets, bouton « Préparer <mois> ») : copie les plafonds de base du mois affiché (défaut ou ajustement) vers le mois suivant pour les budgets cochés (override, ou suppression de l override si égal au défaut), puis affiche ce mois. Le report reste calculé automatiquement en plus.
- Virements automatiques récurrents : `Recurrence.type` = "transfer" + `toAccountId` (même devise, compte différent). Chaque échéance crée 2 opérations internes catégorie « Virements internes » (transfer_out sur le compte source, transfer_in sur la destination, counterpartAccountId croisés, source "recurring"). Prévisionnel : `forecast` renvoie les 2 jambes avec `internal: true` (exclues des revenus/dépenses prévus sauf si les internes sont inclus). Rappels d échéance sur le compte débité ; l alerte de solde bas tient compte des virements auto sortants et entrants. Page Récurrences : type « Virement vers un compte / Pocket », champs Depuis / Vers, carte « Virements auto d ici fin d année », trajet affiché dans la liste.
- Préparation automatique des budgets (lib/budgetPrep.ts, BudgetPrepBanner) : à l ouverture le dernier jour du mois (ou rattrapage les 7 premiers jours du mois suivant), les plafonds du mois écoulé sont copiés sur le mois suivant pour les budgets sans ajustement manuel sur ce mois. Trace dans prefs.budgetPrep[mois] (pending/validated/cancelled, changes avec valeur précédente). Bandeau global « Budgets de <mois> préparés » : Vérifier (/budgets?mois=YYYY-MM), Valider, Annuler (restaure les plafonds). Case « Préparation automatique » sur /budgets (prefs.autoBudgetPrep, activée par défaut). Une seule préparation par mois.

## v5 — trésorerie, imports fiables, UX
- Trésorerie (/tresorerie, lib/cashflow.ts) : simulation jour par jour depuis le solde réel du jour (périmètre « Compte principal + Pockets » par défaut ou un compte), jusqu'au mois choisi (courant → +5). Événements = échéances des récurrences (revenus, charges fixes, virements auto hors périmètre ; virements internes au périmètre neutres ; échéances manuelles en retard ramenées à aujourd'hui) + épargne prévue des objectifs le jour de paie (option) + dépenses variables estimées (moyenne 3 mois hors charges récurrentes, modifiable, réparties par jour). Sorties : point bas + date, 1er jour négatif, paie (plus gros revenu du mois), report nécessaire (min du cumul des flux du mois depuis 0), budget du mois (prévu/reçu/restant), message « Votre solde projeté devient négatif le … Il vous faut X € … avant l'arrivée du salaire le … ». Bouton de création de la récurrence Salaire (validation manuelle) si détecté. Prefs : cashScope, cashVariable, cashIncludeVariable, cashGoalSavings.
- Tableau de bord : bloc 4 questions (TodayOverview) + courbe de trésorerie du mois, alerte si négatif.
- Récurrences : `manual` (pas d'auto-création → « En retard » + Rattraper/Marquer payée via postRecurrence), `skips` (sauter une échéance), `amountOverrides` (montant exceptionnel d'une échéance), statut du mois Payée/À venir/En retard, cumul par récurrence.
- Imports (CsvImportDialog) : CSV et Excel (xlsx via SheetJS), Revolut détecté (sections → compte cible au choix), colonne solde, erreurs par ligne, doublons (date+description+montant+compte, + solde si connu), rapprochement par compte (chaîne des soldes ; 1re ligne en écart surlignée ; solde relevé vs calculé), rapport d'import, historique `data.imports` avec Annuler (retire les opérations `importId`) et Retraiter (réapplique les règles).
- Opérations : étiquettes globales (`tags`, défauts vacances/vélo/projet/remboursable), pièces jointes (`attachments`, data URL ≤ 3 Mo, IndexedDB), recherche globale (barre du haut, `/` ou Ctrl+K → /operations?q=), filtres enregistrés (`data.savedFilters` + intégrés : dépenses voiture de l'année, récurrentes, à vérifier, #remboursable), filtre Nature récurrente/ponctuelle (lib/smart.ts), suggestion de catégorie d'après les opérations similaires (confiance, « faible » < 60 %) avec application aux similaires, trajet des virements internes affiché.
- Règles : `match` all/any (ET/OU) ; règles ajoutées par migration (rulesVersion 2) : Netflix < 20 €, Hetzner OU IONOS.
- Budgets : alerte au-delà de 75 % ; échéances récurrentes restant à venir dans le mois par budget.
- Épargne : type Dette (montant dû, mensualité, fin prévue), compte/Pocket lié (`accountId`), provenance des versements (`GoalMove.source`), archivés avec total épargné et durée, intérêts cumulés affichés à part.
- Annuler / corbeille : `checkpoint` + `undo()` (session, bouton ↶ et Ctrl+Z, toasts « Annuler ») ; corbeille persistée 30 j (`data.trash`) pour opérations, objectifs, récurrences, budgets, restaurable depuis Données.
- Sauvegardes : copie locale automatique quotidienne (IndexedDB, 7 conservées), restaurer / télécharger / sauvegarder maintenant (Données). Export des objectifs CSV/JSON.
- Mode sombre et densité compacte (prefs.theme / prefs.density, classes `dark` / `compact` sur <html>). PWA : manifest, icônes 192/512, service worker réseau d'abord.
- Choix conservés : « Vers le compte d'investissement » reste une dépense (choix initial de l'utilisateur).
